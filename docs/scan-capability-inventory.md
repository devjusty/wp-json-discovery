# Scan Capability Inventory

Status vocabulary is intentionally limited to `retained`, `redesigned`, `deferred`, and `removed`. R0 decisions describe the approved reset: preserve useful investigative coverage, move coordination to Scan Session and evidence-centered findings, and separate investigator and admin workspaces. R1 targets are migration seams, not new legacy response contracts.

## Completeness notes

- Explicit requested rows are present: REST discovery, homepage scan, sitemap scan, domain recon, history, unsupported namespaces, plugin/theme registries, asset intelligence, retention, database health, maintenance, and admin authentication/authorization.
- Additional discovered capabilities are classified above: content footprint, exposure probes, performance snapshot, findings/evidence presentation, scan-session lifecycle/recovery, saved scans/recent runs, notes, and activity logs/heartbeat.
- No current capability is classified `removed`. R0 removal means not carrying a capability forward without evidence; no listed current surface has enough evidence in this repository to make that irreversible decision safely.
- The source inventory is implementation evidence, not product usage evidence. See `docs/research/2026-09-09-r0-research-brief.md` for log limitations and validation work.
